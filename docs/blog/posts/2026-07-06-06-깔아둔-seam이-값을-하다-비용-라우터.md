# 깔아둔 seam이 값을 하다 — 복잡도 비용 라우터를 게이트웨이 데코레이터로

> 2026-07-06 · mint-agent 개발기 #06 · Phase 2(신뢰 레이어 1차) 착수
> **요약:** 지난 다섯 슬라이스 내내 "나중에 여기 꽂는다"며 남긴 `core.llm` 게이트웨이 seam.
> 이번에 그 위에 **복잡도 기반 비용 라우터**를 얹었다. 핵심은 라우터가 *또 하나의 게이트웨이*가
> 되게 한 것 — 어댑터는 자기가 감싸졌는지도 모른 채 라우팅·비용 계측을 공짜로 얻는다. 그리고
> 가격은 **지어내지 않고 운영 코드에서 상속**했다. 누적 테스트 267개 green.

---

## 문제 (Problem)

[#04](2026-07-01-04-이식의-3가지-주입-패턴.md)의 마지막 문장은 이랬다: *"Phase 2 — 이 게이트웨이
seam 위에 비용 라우터를 얹는다. 주입 지점을 미리 파둔 덕에, 어댑터 코드 변경 없이 계측이 들어온다."*
그 약속을 지킬 차례다. 그런데 막상 얹으려니 두 개의 함정이 있었다.

**함정 1 — 어떻게 끼워야 어댑터를 안 건드리나?** seo·review·persona·orchestrator는 이미
`gateway.complete(...)`를 호출한다. 라우팅을 넣겠다고 이 호출부를 전부 고치면, 이식 내내 지켜온
"엔진/어댑터 코드 불변"이 깨진다.

**함정 2 — 비용을 어떻게 정직하게 계산하나?** "비용 라우터"라면서 토큰 단가를 내가 지어내면,
그건 이 프로젝트가 가장 경계하는 것(그럴듯한 허구)이다. inventory도 원본에 **중앙 복잡도 라우터가
없음**을 이미 확인해 뒀다 — 모델 선택은 per-call 플래그였고, `claude_runner`가 비용 *추정*만 했다.

> **질문: 라우팅·계측을 어댑터 0줄 변경으로 끼우면서, 비용 수치는 지어내지 않으려면?**

## 접근 (Approach)

**① 라우터를 게이트웨이 포트로 만든다(데코레이터).** 이게 이번 편의 핵심 한 수다. `CostRouter`가
`LLMGateway`를 *구현*한다. 그러면 라우터는 게이트웨이를 감싸면서 동시에 게이트웨이인 척할 수 있다 —
호출부는 `GeminiGateway()`를 받았는지 `CostRouter(GeminiGateway())`를 받았는지 구분하지 못한다.

```python
class CostRouter:                                  # 자신이 LLMGateway 포트를 구현한다
    def __init__(self, gateway, *, route=DEFAULT_ROUTE, sink=None): ...

    @property
    def available(self): return self._gw.available  # 위임

    def complete(self, system, prompt, *, model=AUTO, temperature=0.4, json_mode=True):
        chosen, cls = self.route_for(system, prompt, model=model, json_mode=json_mode)
        text = self._gw.complete(system, prompt, model=chosen, ...)   # 실제 호출은 위임
        self._emit(CallRecord(model=chosen, cost_usd=..., ...))        # 계측은 한 곳에서
        return text
```

`model="auto"`면 복잡도로 모델을 고르고, 구체 모델을 명시하면 그대로 통과시키되 **둘 다 계측**한다.
어댑터를 감싸는 순간 라우팅·비용 로깅이 코드 변경 0줄로 들어온다.

**② 복잡도 분류는 순수 휴리스틱으로.** "어려운 일엔 비싼 모델, 쉬운 일엔 싼 모델"을 투명한 가산
점수로 정했다 — 고난도 키워드(분석·설계·디버그·추론)는 +, 저난도(요약·분류·추출)·짧은 길이·구조화
출력은 −. 점수로 티어(CHEAP/BALANCED/DEEP)를 가르고, **왜 그 티어인지 근거를 남긴다**. 순수
함수라 학습 기반 추정으로 갈아끼울 자리도 열려 있다.

**③ 가격은 상속한다, 지어내지 않는다.** 단가표·비용 공식은 운영 `claude_runner._PRICING`/
`_estimate_cost`에서 그대로 가져왔다(출처가 붙은 수치). 기본 라우트도 *가격표에 단가가 있는*
모델로만 구성했다. 공시가는 변하므로 "검증·갱신하라"는 주석과 함께, 라우트·가격을 전부 주입
가능하게 뒀다 — 최신 모델은 현재가와 함께 설정으로 교체.

**④ 엔진 범용성은 토이 라우트로 증명한다.** control 편에서 라우터가 `add (\d+)` 같은 토이 룰로도
돌아 "youtube를 모른다"를 증명했듯, 이번엔 `toy-cheap/mid/deep` 라우트와 가짜 게이트웨이로 **Claude
조차 몰라도** 라우팅이 돎을 고정한다:

```python
# 라우터는 Claude를 모른다 — 토이 라우트 + 가짜 게이트웨이로 결정적 검증
router = CostRouter(fake_gw, route={Tier.DEEP: "toy-deep", ...}, sink=records.append)
router.complete("", "이 아키텍처를 분석·리팩터해줘", model="auto")
assert fake_gw.calls[0]["model"] == "toy-deep"       # 고난도 → DEEP 티어로 라우팅
assert records[0].cost_usd == estimate_cost("toy-deep", ...)   # 계측까지 결정적
```

가격 공식이 원본과 같은지도 parity로 못 박는다 — opus급 `(1000·15 + 1000·75)/1e6 = 0.09`.

## 배움 (Learnings)

**1. 데코레이터가 포트를 구현하면, 삽입이 공짜다.** 라우터를 게이트웨이의 *하위 타입*으로 만든
한 수가 전부를 갈랐다. 어댑터는 감싸졌는지 모르고, 라우팅·계측은 0줄 변경으로 들어온다. "끼우는
것"과 "끼워지는 것"이 같은 포트를 말하면, 그 사이에 무엇이든 넣을 수 있다.

**2. seam은 미리 팠기 때문에 값을 한다.** 이건 새 통찰이 아니라 [#04](2026-07-01-04-이식의-3가지-주입-패턴.md)의
약속이 회수된 순간이다. 다섯 슬라이스 동안 "나중에 여기"라고 남긴 주입점이 없었다면, 오늘 라우터는
어댑터 열 곳을 헤집는 작업이었을 것이다. 추상화의 값은 *만들 때가 아니라 회수될 때* 증명된다.

**3. "지어내지 않기"는 설계로 강제한다.** 비용 수치를 정직하게 유지하는 방법은 다짐이 아니라
구조다 — 단가를 운영 코드에서 *상속*하고, 없는 값은 라우트에서 *배제*하고, 근사인 것(토큰 추정)은
*근사라고 이름 붙이고*, 아직 안 된 것(실측 usage·실배선)은 🔜로 *분리*한다. 정직성은 라벨이 아니라
코드가 지킨다.

**4. 완성과 미완성을 같은 문장에서 구분한다.** "비용 라우터 ✅"라고만 쓰면 과장이다. "엔진 작동 ✅,
파이프라인 실배선 🔜"이라 써야 검증 가능하다. 포트폴리오에서 가장 신뢰를 얻는 문장은 자기가 아직
안 한 것을 정확히 아는 문장이다.
