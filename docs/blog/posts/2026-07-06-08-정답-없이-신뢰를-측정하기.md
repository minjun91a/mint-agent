# 정답 없이 신뢰를 측정하기 — eval · 교정 · 컨센서스

> 2026-07-06 · mint-agent 개발기 #08 · Phase 2(신뢰 레이어 1차)
> **요약:** "신뢰 레이어를 만들었다"를 어떻게 증명하나? 정답 라벨이 없는데 검증 게이트의 품질을
> 어떻게 재나? Phase 2에서 세 조각으로 답했다 — **자체 모순 감사(eval)**, **발견→교정→재확인
> 루프(find→fix→verify)**, **N개 리뷰어 컨센서스**. eval은 실 운영 로그에서 진짜 결함을 잡았고,
> 그 결함을 이식본에서 고쳐 루프를 닫았다. 누적 테스트 334개 green.

---

## 문제 (Problem)

[#06](2026-07-06-06-깔아둔-seam이-값을-하다-비용-라우터.md)에서 게이트웨이 seam 위에 비용 라우터를
얹었다. 이제 신뢰 레이어의 본체 — **검증(verify)** 차례다. 그런데 검증에는 고약한 자기참조
문제가 있다:

- **검증 게이트가 스스로 틀리면 누가 잡나?** 발행 전 컴플라이언스 게이트는 콘텐츠를 판정한다.
  그런데 그 게이트의 판정 자체가 틀렸는지는 무엇이 검사하나?
- **정답 라벨이 없다.** "이 콘텐츠는 위반"이라는 ground truth 데이터셋이 없다. 운영 로그
  (`compliance_audit_*.jsonl`)에 있는 건 게이트가 *내린 결정*이지, *옳은 답*이 아니다.
- **한 판정을 믿어도 되나?** LLM 리뷰어 하나의 판정은 그럴듯하지만 틀릴 수 있다.

> **질문: 정답 라벨 없이, 검증 게이트의 품질을 어떻게 측정하고 개선하는가?**

## 접근 (Approach)

세 조각으로 나눠 답했다. 각각이 "정답 없이"의 다른 답이다.

**① 정답 대신 '자기모순'을 잰다 (eval 하니스).** 옳은 답은 몰라도, 게이트가 *자기 규칙과
모순되는지*는 라벨 없이 검사할 수 있다. 예컨대 "reject인데 passed=true"는 무조건 버그다.

```python
# core/trust/eval.py — 정답 라벨 없이 검사 가능한 논리적 불변식
def check_invariants(records):
    for r in records:
        if not (0.0 <= r.score <= 1.0):              # score는 [0,1] 스펙
            add("score_range", ...)
        if r.recommendation == "reject" and r.passed: # reject면 통과일 수 없다
            add("reject_implies_not_passed", ...)
        if r.recommendation == "approve" and not r.passed:
            add("approve_implies_passed", ...)
```

이 하니스를 **실 운영 로그 36건**에 돌리자 곧바로 걸렸다 — **7건이 `score=40` 같은 스펙 위반**.
LLM 심층 리뷰어가 점수를 [0,1]로 정규화하지 않고 뱉은 것이다. 정답 라벨 하나 없이, 실제 데이터
품질 결함을 잡았다.

**② 발견을 교정으로 닫는다 (find→fix→verify).** 측정은 고칠 때 값을 한다. eval이 잡은 결함을
이식본에서 실제로 교정했다 — 원본과 *의도적으로 다르게*:

```python
# adapters/youtube/review.py — 원본은 미정규화 점수를 그대로 통과시켰다. 계약[0,1]에 맞게 클램프.
score=max(0.0, min(1.0, raw_score)),
recommendation=raw_rec if raw_rec in ("approve", "review", "reject") else "review",
```

그리고 고쳤음을 **같은 eval로 재확인**하는 테스트를 남겼다: 교정된 Verdict를 감사 레코드로
만들어 `check_invariants`가 빈 목록을 반환하는지 본다. 발견→교정→재확인이 코드로 닫혔다.

**③ 한 판정을 믿지 않는다 (컨센서스).** 같은 콘텐츠를 N개 리뷰어로 교차검증하고, 보수적으로
결합한다. 리뷰어들이 갈리면(`disagree`) 그 자체가 신호 — 사람이 봐야 한다.

```python
# core/trust/consensus.py — 하나라도 reject면 reject, 전원 approve여야 approve
def combine(verdicts):
    votes = [v.recommendation for v in verdicts]
    agreement = "consensus" if len(set(votes)) == 1 else "disagree"
    # 가장 안전한 표 채택 + 전원 통과여야 passed + score는 최댓값(최악 위험도)
```

리뷰어는 **주입**이라 엔진은 몇 개의 모델을 쓰는지 모른다. 순수 `combine`은 실 LLM 없이
결정적으로 검증된다.

## 결과 (Result)

**신뢰 레이어의 측정 사이클 (🟢):**

| 조각 | 무엇 | "정답 없이"의 답 | 커밋 |
|---|---|---|---|
| eval 하니스 | 게이트 로그 집계 + 자체 모순 감사 | 정답 대신 자기모순을 잰다 | `31c6f52` |
| 결함 교정 | LLM 경로 score 클램프·rec 검증 | 발견을 교정으로 닫는다 | `8fc909f` |
| 컨센서스 | N 리뷰어 교차검증·보수적 결합 | 한 판정을 믿지 않는다 | `37bcfed` |

- **`pytest` → 334 passed** (이 세 조각에서 +33, 전부 실 LLM·네트워크 없이).
- **실 데이터 검증:** 운영 로그 36건에서 pass_rate 2.78%, agreement consensus 15/disagree 21,
  **모순 7건 검출**(전부 score-range). 정답 라벨 0개로 진짜 결함을 잡았다.
- **정직성:** 검출한 결함을 숨기지 않고 로드맵에 남긴 뒤 교정했다. 컨센서스는 원본
  `double_check` 소스가 부재해 *이식이 아니라 재구성*임을 코드·문서에 명시했다.

## 배움 (Learnings)

**1. 정답이 없어도 '자기모순'은 잴 수 있다.** ground truth 데이터셋을 기다리면 아무것도 측정
못 한다. 하지만 "reject면 통과일 수 없다" 같은 *논리적 불변식*은 라벨 없이 오늘 검사 가능하다.
완벽한 평가를 미루는 대신, 지금 가능한 감사부터 돌리니 진짜 결함이 나왔다.

**2. 측정은 교정으로 닫힐 때 값을 한다.** eval이 `score=40`을 리포트만 하고 끝났다면 대시보드
장식이다. 그 결함을 이식본에서 고치고, 고쳤음을 같은 eval로 재확인하는 루프를 닫아야 —
"측정→개선"이 실제로 돈다. find→fix→verify는 한 슬라이스로 완결됐다.

**3. 불일치는 버그가 아니라 신호다.** 컨센서스에서 리뷰어들이 갈리는 건 실패가 아니다. 그 `disagree`가
"여긴 사람이 봐야 한다"를 가리킨다. 자동화의 목표는 모든 걸 자동 결정하는 게 아니라, *언제 사람을
불러야 하는지*를 자동으로 아는 것이다.

**4. 정직은 결함을 노출하고 부재를 표시하는 것이다.** eval이 잡은 실 데이터 결함을 숨기지 않았다.
컨센서스의 원본 소스가 없다는 사실도 "재구성"이라 명시했다. 신뢰 레이어를 만들면서 스스로에게
정직하지 않으면, 그 레이어는 신뢰할 수 없다.
