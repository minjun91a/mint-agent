# 경계는 '무지(無知)'로 증명된다 — Phase 1을 닫으며

> 2026-07-06 · mint-agent 개발기 #07 · Phase 1(엔진/어댑터 경계 분리) **완료**
> **요약:** 남은 두 조각(control `dispatch`, 2중 결합 분해)을 옮기며 Phase 1을 닫았다. 두 조각의
> 공통 교훈은 하나 — **경계는 폴더 이름이 아니라 "엔진이 무엇을 *모르는가*"로 증명된다.** 엔진은
> 어떤 intent가 무슨 일을 하는지 모르고(핸들러 주입), YouTube도 Discord도 모른다(포트·주입).
> 누적 테스트 301개 green.

---

## 문제 (Problem)

produce·엔진 5모듈까지 옮기고 나니 Phase 1의 마지막 두 개가 남았다. 둘 다 "경계가 진짜인가"를
정면으로 묻는 것들이었다:

- **control `dispatch`** — 자연어를 intent로 라우팅(`parse`)하는 건 이미 갈랐지만, intent를 *실제
  행동*으로 잇는 `dispatch`는 미뤄뒀다. 원본은 `if intent == "story": from tools.story_pipeline …`
  처럼 **미이식 파이프라인을 직접 import**하는 if/elif 덩어리였다. 엔진에 두면 엔진이 youtube
  파이프라인을 알게 된다.
- **2중 결합 분해** — [inventory](../../inventory.md)가 처음부터 지목한 난제. 결합면은 "유튜브 하나"가
  아니라 **YouTube(출력)·Discord(IO) 둘**이다. YouTube는 `YouTubeAdapter`로 뺐지만, Discord 채널
  → 페르소나 매핑이 아직 **youtube 콘텐츠 모듈 안에** 박혀 있었다.

> **질문: 폴더를 `core/`와 `adapters/`로 갈라놓기만 하면 경계인가? 무엇이 "진짜 분리됐다"의 증거인가?**

## 접근 (Approach)

두 조각을 같은 원리로 닫았다 — **엔진에서 "아는 것"을 덜어낸다.**

**① dispatch = 핸들러 주입.** 엔진은 라우팅만 하고, "그 intent가 무슨 일을 하는지"는 주입받는다.

```python
# 엔진(core.control): intent가 뭘 하는지 모른다 — 핸들러를 받아 부를 뿐
def dispatch(cmd, handlers):
    if cmd.intent == "unknown":
        return {"ok": False, "msg": "unknown intent"}
    handler = handlers.get(cmd.intent)
    if handler is None:
        return {"ok": False, "msg": f"디스패처 미구현: {cmd.intent}"}  # 없는 건 정직하게
    return handler(cmd)
```

youtube는 intent→파이프라인 매핑을 `build_handlers`로 제공하되, **파이프라인 자체는 콜러블로
주입**한다. 아직 안 옮긴 파이프라인은 주입하지 않으면 그만 — 엔진이 "미구현"으로 정직하게 답한다.
원본의 IO 결합(`discord=True`)은 콜러블 뒤로 밀어 여기서 지운다.

**② 2중 결합 분해 = Discord를 콘텐츠에서 들어낸다.** 핵심은 **의존 방향**이었다. 채널→페르소나
매핑은 "Discord가 youtube 콘텐츠를 *소비*하는" IO 관심사다. 그러니 방향은 **IO → 콘텐츠**여야 한다:

```python
# adapters/discord/personas.py — IO(discord)가 콘텐츠(youtube)를 고른다 (올바른 방향)
from adapters.discord.channels import channel_key_from_env   # Discord 채널 정체성
from adapters.youtube.persona import build_registry          # youtube 페르소나 정의

def resolve(channel_id):
    return build_registry(channel_key=channel_key_from_env).resolve(channel_id)
```

그 결과 `adapters/youtube/persona.py`는 **Discord를 import조차 하지 않는다.** 페르소나 *정의*만
남고, 채널 해석기는 주입받는다. 엔진 `PersonaRegistry`는 애초에 resolver를 주입받으므로 Discord도
YouTube도 모른다.

**증명은 테스트가 한다 — 엔진이 정말 "모르는지" 본다:**

```python
# dispatch 엔진은 youtube를 모른다 — 토이 intent/핸들러로도 돈다
assert dispatch(Command(intent="toy"), {"toy": lambda c: {"ok": True}})["ok"]

# youtube persona는 Discord를 모른다 — 해석기 없으면 채널 라우팅이 아예 없다
assert resolve("12345").key == "default"          # Discord 매핑? youtube는 모른다
```

## 결과 (Result)

**Phase 1을 닫은 두 조각 (🟢):**

| 조각 | 엔진(`core/`) | 어댑터 | 핵심 | 커밋 |
|---|---|---|---|---|
| dispatch | `dispatch(cmd, handlers)` | youtube `build_handlers`(파이프라인 주입) | 엔진은 intent 의미를 모름 | `88dd3d5` |
| 2중 결합 분해 | `PersonaRegistry`(resolver 주입) | `adapters/discord/`(IO) ↔ `adapters/youtube/`(콘텐츠) | 방향 IO→콘텐츠, youtube는 Discord 무지 | `cfe5bb8` |

- **`pytest` → 301 passed** (이 두 조각에서 +24, 전부 실 파이프라인·네트워크 없이).
- **원본 parity:** dispatch의 arg 추출(`no_upload`·`category`/`model`·`shorts`·`query`/`top`), Discord
  채널 env 매핑 — 원본과 동일.
- **경계 증명:** 엔진 dispatch가 토이 핸들러로, youtube persona가 Discord 없이 돈다. **폴더가
  아니라 "무지"가 경계를 증명한다.**

**Phase 1 완료** — `core/`(llm·routing·gateway·memory·pipeline·control·persona·orchestrator·trust)는
플랫폼(YouTube·Discord)을 모른 채 포트로만 의존하고, 플랫폼 로직은 어댑터에 격리됐다.

**정직하게 안 한 것:** 실제 Discord 봇 런타임(`discord_bot`·`notifier`·`approvals`)은 이식하지
않았다 — Phase 1은 *경계 분리*이지 *IO 런타임 이식*이 아니다("일반화는 2번째가 강제할 때"). 미이식
파이프라인은 dispatch에서 "미구현"으로 드러나고, engineer 페르소나의 잔여 Discord 문자열
(`perms_env_key`)은 권한 시스템 이식 시 정리로 남겨뒀다.

## 배움 (Learnings)

**1. 경계는 폴더가 아니라 무지로 증명된다.** `core/`에 넣었다고 엔진이 되는 게 아니다. 엔진이
youtube intent를, Discord 채널을 *모른 채* 도는 걸 테스트가 보일 때 비로소 경계다. "이름만 core인
코드"와 "진짜 엔진"을 가르는 건 위치가 아니라 이 무지의 증명이다.

**2. 못 옮긴 것은 막지 말고 드러낸다.** dispatch는 미이식 파이프라인을 `NotImplementedError`로
막지 않는다. 주입 안 하면 "미구현"이라 답할 뿐이다. 구조는 지금 완성하고, 없는 건 실행 시점에
정직하게 보인다 — 이게 이식 내내 지킨 태도다.

**3. 결합은 방향을 가진다.** "Discord와 youtube를 분리"는 모호하다. 정확히는 *IO가 콘텐츠를
소비*하므로 discord→youtube 한 방향만 남기고 반대(youtube→discord)를 0으로 만드는 것이다. 방향을
정하니 어느 모듈에서 무엇을 들어낼지가 자명해졌다.

**4. "완료"는 안 한 것을 아는 것까지 포함한다.** Phase 1 완료 = "봇 런타임은 범위 밖"을 명시하는
것. 무엇을 증명했고 무엇을 남겼는지 정확히 말할 수 있을 때 마일스톤을 닫는다. 포트폴리오에서
신뢰를 주는 건 다 했다는 주장이 아니라, 경계를 정확히 아는 문장이다.

  가변 복잡도 경로에 `model="auto"` 라우팅을 옵트인한다.
- **실측 usage 연동** — 게이트웨이 포트가 provider usage를 노출하게 확장해, 토큰 근사를 실측으로.
- **eval 하니스** — 운영 `compliance_audit_*.jsonl`로 환각·위반을 자동 채점. trust 레이어의 첫 지표.
