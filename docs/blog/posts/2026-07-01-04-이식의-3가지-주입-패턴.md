# 이식의 3가지 주입 패턴 — 무엇을 주입하느냐가 곧 무엇이 불확실하냐다

> 2026-07-01 · mint-agent 개발기 #04 · Phase 1(엔진/어댑터 경계 분리)
> **요약:** LLM·외부 API·파일/시간/난수가 한 함수에 엉킨 운영 모듈 5개를 옮기며, "무엇을
> 주입하느냐"로 세 가지 이식 패턴이 굳었다. 각 패턴은 *과거엔 테스트가 불가능했던* 로직
> (검열 폴백·프로바이더 교체·트로프 dedup)을 결정적으로 고정한다. 누적 테스트 143개 green.

## 문제 (Problem)

앞선 편들에서 옮긴 건 대체로 순수하거나(자막·클립) 파일 하나에 의존하는(메모리) 모듈이었다.
이번에 남은 건 성격이 다르다 — **스크립트 생성(OpenAI), SEO(Gemini), 이미지(FLUX→DALL-E
폴백+검열 재시도)**. 이런 모듈은 한 함수 안에 이질적인 불확실성이 뒤엉켜 있다:

```python
# 원본 image_gen — 외부 호출·랜덤·시간·파일이 한 덩어리
def generate(prompt, output_path, ...):
    provider = _cfg()["provider"]          # 파일
    try:
        return _generate_flux(prompt, ...)  # 네트워크 + rate-limit(time.sleep) + 전역상태
    except Exception:
        return _generate_dalle(prompt, ...) # 또 네트워크 + 검열 재시도 3단
```

브리프의 원칙은 "**특성화 테스트로 원본과 동일함을 보증한 뒤에 옮긴다**"(8장)이다. 그런데 이런
코드는 API 키가 있어야 돌고, 돌아도 결과가 매번 다르다. 특성화가 원천적으로 막힌다.

> **질문: 비결정·외부 의존 코드를 어떻게 *결정적으로* 이식하는가?**

## 접근 (Approach)

답은 하나였다 — **불확실한 부분을 밖에서 주입받게 만든다.** 그런데 옮기다 보니 "주입하는
대상"이 모듈 성격에 따라 세 갈래로 갈렸다. 이게 이번 편의 핵심이다.

**패턴 ① LLM → 게이트웨이 주입.** seo·review·story_writer의 흩어진 SDK 호출을 엔진의
`core.llm.LLMGateway` 포트 하나로 모았다. 테스트는 가짜 게이트웨이(canned JSON)를 넣는다.
seam을 한 번 뽑으니 **2번째 프로바이더가 공짜로 끼워졌다** — 같은 `complete` 포트가
Gemini(`system_instruction`)와 OpenAI(chat `messages`)에 동일하게 매핑된다:

```python
class LLMGateway(Protocol):                       # 엔진이 아는 유일한 계약
    @property
    def available(self) -> bool: ...
    def complete(self, system, prompt, *, model, temperature=0.4, json_mode=True) -> str: ...

# GeminiGateway·OpenAIGateway가 각자 SDK를 이 포트 뒤로 숨긴다.
# → 프로바이더가 늘어도 seo/review/story_writer 코드는 0줄 변경.
```

**패턴 ② 외부 API·바이너리 → 백엔드(저수준 콜러블) 주입.** publish(YouTube 업로드)·
image_gen(FLUX/DALL-E)은 "응답 정규화"가 아니라 "부수효과가 있는 호출"이다. 그래서 게이트웨이가
아니라 **백엔드 객체**에 저수준 콜러블(`run`/`download`/`image_url`)을 주입한다. 덕분에 실
API 없이 *검열 폴백 로직*을 결정적으로 재현할 수 있다 — 원본에선 불가능했던 일이다:

```python
def test_dalle_retries_on_policy_then_succeeds(tmp_path):
    calls = []
    def image_url(cfg, prompt):
        calls.append(prompt)
        if len(calls) == 1:
            raise Exception("content_policy blocked")   # 1차: 검열 차단
        return "http://img/ok.png"                       # 2차: 성공
    out = DalleBackend({}, image_url=image_url, download=_fake_dl).generate("epic battle", ...)
    assert calls[1] == sanitize_prompt("epic battle")    # 안전화 프롬프트로 재시도했다
```

**패턴 ③ 파일·시간·난수 상태 → 경로·clock·rng 주입.** story_writer의 트로프 선택은
`datetime.now()`·`random`·하드코딩 경로에 묶여 있었다. `TropeLibrary(tropes_path=…,
used_log_path=…, now=…)`로 셋을 전부 주입받게 바꾸니, "48시간 내 사용 제외" 같은 시간 의존
로직이 고정된 시계 아래서 결정적으로 검증된다. (이 패턴의 원형은 앞서 옮긴 `core/memory`의
DB 경로 주입이다 — 여기서 시간·난수까지 일반화했다.)

## 배움 (Learnings)

**1. "무엇을 주입하느냐"는 "무엇이 불확실하냐"의 거울이다.** LLM은 *비결정 응답*, 외부 API는
*네트워크·키·부수효과*, 상태는 *시간·난수·위치*. 불확실성의 종류가 주입 지점을 결정한다.
패턴을 외워서 고른 게 아니라, 모듈의 불확실성을 보니 자연히 갈라졌다.

**2. 주입 seam은 재사용된다.** 게이트웨이를 한 번 뽑는 비용은 seo 하나였지만, review·
story_writer가 그 위에 얹혔고 2번째 프로바이더까지 공짜로 붙었다. seam은 만들 때가 아니라
*재사용될 때* 값을 회수한다.

**3. 주입은 "과거엔 못 짜던 테스트"를 연다.** 검열 차단→안전화 재시도, FLUX 실패→DALL-E
폴백 — 실 API로는 재현조차 어려운 경로다. 저수준 호출을 주입하니 "1차 차단, 2차 성공"을
한 줄로 재현한다. 리팩터가 커버리지를 *넓혔다*, 유지가 아니라.

**4. 원본은 끝까지 안 건드린다.** 운영 중인 youtube-agent는 무수정이다. 옮긴 사본만 주입
가능하게 재구성하고, 순수부는 parity로 "정말 같은가"를 증명한다. 개발기는 커밋으로 "글 ↔
코드"가 묶여 있어, 이 주장들은 전부 검증 가능하다.
