# 왜 youtube-agent와 trust-layer를 mint-agent로 합치나 — Phase 0

> 2026-06-18 · mint-agent 개발기 #01 · Phase 0(정리 & 결정)
> **요약:** 운영 중인 YouTube 자동화와 신뢰 레이어를 한 시스템으로 합치기로 결정. 코드는 한 줄도
> 안 고치고, *현황 검증 → 결정 → 안전망 → 분류*만 했다. 그 과정에서 "안다고 생각한 구조"와
> 실제 코드가 여러 군데 달랐고, 운영 코드에 안전망(git)을 까는 실수에서 교훈을 얻었다.

---

## 문제 (Problem)

몇 달째 돌아가는 YouTube 자동화(`youtube-agent`)가 있다. 자동으로 영상을 찍어내지만,
혼자 두면 불안하다 — **AI가 가끔 없는 내용을 지어내고(환각), 비용이 예측 안 되고, 무엇을
하는지 안 보인다.** 여기에 "검사·관리하는 신뢰 레이어"를 붙이고 싶었다.

그런데 막상 시작하려니 출발선이 불분명했다:
- 내 코드가 **실제로 어디 있는지**조차 문서와 달랐다.
- 운영 중인 코드인데 **git이 없어** 손대면 되돌릴 수 없었다.
- "엔진"과 "유튜브 전용" 코드의 경계가 머릿속에만 있었다.

## 접근 (Approach)

Phase 0의 목표를 코딩이 아니라 **출발선 정리**로 잡고 넷을 했다:

1. **환경 검증** — 코드가 실제로 어디 있는지 명령으로 확인(추측 금지).
2. **결정 3가지 확정** — 레포 전략 / 안전망 / 두 번째 어댑터.
3. **git 안전망** — 운영 코드에 되돌리기 기준점부터.
4. **엔진/어댑터 분류표** — 무엇이 "엔진"이고 무엇이 "출구"인지 전수 분류.

## 배움 (Learnings)

**1. 문서를 믿지 말고 코드를 읽어라.** 온보딩 문서는 루트를 `C:\MINT\`로, 특정 자산(`AGENT_REGISTRY`,
`cleanup-execution-log.md`)이 있다고 적었지만 — 코드엔 그 이름이 없었다. 문서는 과거의 스냅샷이다.
분류·결정은 *지금 코드*에 맞춰야 한다.

**2. 비가역 행위는 "실행 전 검증"으로 막아라.** 안전망을 만들며 `.gitignore`에 이렇게 적었다:

```gitignore
output/             # 생성 미디어 352MB
.env.bak            # .env 백업 (시크릿)
```

**`.gitignore`는 인라인 주석을 지원하지 않는다.** `output/  # ...` 전체가 하나의 패턴이 돼
매칭에 실패했고, 시크릿 백업과 354MB가 통째로 스테이징됐다. 다행히 **커밋 직전 스테이징을
검사하는 게이트**를 둔 덕에 잡았다:

```bash
git diff --cached --name-only | grep -E '\.env|credentials/|\.pickle|^output/' && echo STOP
```

또 배운 것: `.gitignore`는 **이미 추적된 파일엔 적용되지 않는다.** 패턴을 고쳐도 안 빠져서,
인덱스를 비우고 처음부터 다시 스테이징해야 했다. → **자동화는 빠르게 틀린다. 게이트가 없으면
실수가 그대로 굳는다.** (상세: [ADR 0002](../../adr/0002-git-안전망-우선.md))
