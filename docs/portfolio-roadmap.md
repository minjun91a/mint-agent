## 목표와 완료 기준

제조 시나리오 하나를 처음 보는 사람이 재현하고,
개발자가 생성·검증·승인·저장의 경계를 코드로 설명할 수 있는 대표작으로 마감한다.

아래 순서는 현재 코드와 문서의 차이에 대한 제안이다.
기존 [개발 로드맵](roadmap.md)의 Phase 이력과 [코드 이해 리뷰](review-roadmap.md)는 유지한다.
특히 R0의 CODE_MAP은 본인이 작성하는 작업이며, 이 문서는 이를 대신하지 않는다.

마감 조건:

- [x] 새 환경에서 오프라인 데모와 전체 테스트를 안내대로 실행할 수 있다.
- [ ] 제조 CLI의 승인·거절·보류·API 실패를 재현하고 발행 여부를 설명할 수 있다.
- [x] 수량·날짜가 틀린 초안의 처리 정책과 그 회귀 검사가 있다.
- [x] 정답과 기대 판정을 고정한 합성 평가셋 및 오프라인 정책 평가 결과가 있다. 사람 독립 검수는 남음.
- [ ] 실제 모델 실행의 환경·비용·지연·검증 범위를 구분한 기록이 있다.
- [ ] 본인이 핵심 경로·설계 선택·AI 보조 개발 중 검토한 내용을 설명할 수 있다.

## P1 — 핵심 경로 이해와 발행 정확성

**먼저 읽을 경로:** `run_manufacturing.run` → `ManufacturingAdapter.produce` →
영향 계산·초안 생성 → `gate` → `approval.resolve` → `publish`.

본인 학습 리뷰는 R0~R6의 순서와 예측 후 실행 원칙을 따른다.
아래 보완은 해당 모듈 리뷰와 연결해 진행한다.

2026-10-23 구현 진행: 명시적인 수량/날짜의 대상·항목 대조와 불명확한 숫자의 사람 검토,
내용에 묶인 일회성 발행 허가를 추가했다. 사람 승인 전 CLI 전체 미리보기도 연결했다.
아래 1·2번의 초기 결함을 보완했으며, 지원 문법과 한계·API 변경은
[제조 검증·승인 설명](manufacturing-validation.md)에 기록했다.
3번은 호출별 제한 시간·재시도 없음·부분 생성 중단·종료 코드 3 정책과 회귀 검사를 추가했다.
고정 합성 사례 42개의 판정·발행 정책도 평가했다.
[API 실패·고정 평가 설명](manufacturing-reliability-eval.md)에 결과와 한계를 기록했다.
실제 모델 실행과 사람의 정답 검수는 남아 있으며, 본인 코드 이해 리뷰 완료를 의미하지 않는다.

| 순서 | 현재 근거 / 문제 | 마무리 작업 | 완료 조건 |
|---|---|---|---|
| 1 | [review.py](../adapters/manufacturing/review.py)는 빈 초안·알려진 코드·일부 정보 노출을 검사하지만 수량·날짜는 대조하지 않음 | 계산 결과와 생성 문장의 수량·날짜를 연결하는 구조화 출력 또는 검증 가능한 템플릿을 선택. 확인 불가능한 주장의 보류 정책도 정의 | 정상 코드에 틀린 수량/날짜를 붙인 사례가 자동 발행되지 않음. 정상 문장과 거절/보류 사례 회귀 검사 |
| 2 | [CLI](../run_manufacturing.py)가 gate→승인→publish를 연결하지만 publish API 자체에는 승인 증거가 없음 | 호출자 책임을 유지할지, 발행 함수가 승인된 결과만 받게 할지 결정. 승인 후 내용 변경도 검토 | 승인 없이 또는 검토 후 바뀐 초안이 발행되는 경계에 대한 정책·검사·문서가 일치 |
| 3 | 키 없음 경로는 검사되지만 SDK import 실패·제공자 오류·타임아웃은 별도 확인 필요 | 세 초안 중 일부 실패, 연결 실패와 재시도 범위를 명시하고 필요한 경계 검사 추가 | 실패 때 파일 생성·부분 성공·종료 코드가 정책대로 동작하고 원인을 진단할 수 있음 |

**범위:** 대표 제조 CLI에 집중한다. 신규 어댑터·웹 UI·Discord 봇 이식은 이 단계의 완료 조건이 아니다.

## P1 — 품질 평가와 실행 재현

### 평가셋

- [x] 정상 / 없는 코드 / 수량 오류 / 날짜 오류 / 정보 노출 / 초안 누락 / 모델 실패를 포함한 고정 합성 사례 42개 작성.
- [ ] 각 사례의 근거 사실과 기대 판정(`approve / review / reject`)을 사람이 확인.
- [x] 개발 29개·예약 13개 분할과 v1 체크섬 기록. 독립 블라인드 분할은 아님.
- [x] 사례별 판정, 혼동 행렬, 위험 자동 발행, 정상 오차단, 사람 검토 건수와 분모 보고.
- [x] 무검증 합성 정책과 같은 입력의 발행 수 비교. 실제 이전 버전 실험·LLM 품질 평가와 구분.

결과: [오프라인 보고서](eval-results/manufacturing-v1.md). 판정·오류 42/42 일치,
정상 오차단 0/10, 위험 초안 자동 발행 0/28, 오류 4건 발행 없음.
다음은 사람이 라벨을 확인하고 실제 모델 출력 사례를 모아 별도 평가하는 작업이다.
[42건 검수 자료와 응답표](manufacturing-model-run.md#먼저-정답을-검수하기)를 준비했으며 전부 미검수 상태다.

**완료 조건:** 테스트 개수 외에 어떤 오류를 잡고 놓치는지, 정상 결과를 얼마나 막는지 설명할 수 있다.

### 새 환경과 실제 모델 실행

실행 준비: [측정 안내](manufacturing-model-run.md)와 오프라인 계획/리허설·명시적 live 실행 도구가 있다.
REST 측정 전송부는 기존 SDK CLI와 구분하며 호출별 사용량·사고/캐시 토큰·비용 추정·지연을 기록한다.
실제 모델 호출이나 사람 검수 완료를 의미하지 않는다.

- [ ] 개발·모델 호출 의존성과 검증한 버전, 환경변수 예제를 정리.
  현재 `requirements-dev.txt`는 제공자 SDK를 설치하지 않으며 제조 CLI는 `.env`를 자동 로드하지 않는다.
- [ ] 별도 새 환경에서 오프라인 데모와 테스트 재현.
- [ ] 모델·SDK·입력 데이터·실행일을 고정하고 실제 모델 시나리오 실행 기록 작성.
  유료 호출은 실행 범위와 비용을 확인한 후 진행.
- [ ] 제조 CLI에서 감사 sink와 비용 observer를 설정하는 방법 결정.
  현재 `gate(adapter, produced)`에는 sink가 없고 `set_observer`도 호출하지 않는다.
- [ ] 요청별 결과·사용량·비용·지연을 기록. 토큰 근사·미가격 모델은 실측과 구분.
- [ ] 실제 ERP 연동 여부와 가상 CSV 입력 범위를 시연에서 명시.

**완료 조건:** 다른 사람이 기록된 환경으로 재현하고, 실제 호출과 테스트 대역을 구분할 수 있다.
현재 단가표만으로 비용 절감 성과를 주장하지 않는다.
