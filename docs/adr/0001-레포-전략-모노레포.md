# ADR 0001 — 레포 전략: 새 모노레포

- **상태(Status):** Accepted
- **날짜:** 2026-06-18
- **관련 Phase:** 0

## 맥락 (Context)

운영 중인 `youtube-agent`(2026-04~)와 아직 코드화되지 않은 신뢰(trust) 레이어를
**하나의 시스템(mint-agent)** 으로 합쳐야 한다. 선택지는 셋이었다:

1. `youtube-agent` 내부에서 리팩터 — 빠르지만 운영 코드와 신규 구조가 뒤섞임.
2. **새 모노레포** — 깨끗한 경계, 단 점진 이식 필요.
3. trust 레이어를 별도 레포로 분리 — 두 약점(데모/콘텐츠팜)을 다시 갈라놓음.

`youtube-agent`는 git조차 없는 상태였고(→ [ADR 0002](0002-git-안전망-우선.md)), 코드 위치도
3곳에 분산돼 있었다(`C:\MINT-agent`, `~/youtube-agent`, 무관한 `C:\MINT`).

## 결정 (Decision)

**새 모노레포** — 이미 존재하던 GitHub `minjun91a/MINT`(클론 `C:\MINT-agent`)를 mint-agent
모노레포로 채택한다. `core/`(엔진) · `adapters/`(플랫폼) · `core/trust/`(cross-cutting)로 구성하고,
`youtube-agent` 운영 코드를 안전망 스냅샷 후 **점진 이식**한다.

## 결과 (Consequences)

- ➕ 엔진/어댑터 경계를 처음부터 깨끗하게 설계 가능.
- ➕ 포트폴리오 서사가 한 repo·한 히스토리로 모임(채용 가독성).
- ➖ 운영 코드를 즉시 옮기지 못하고 이식 비용 발생 → Phase 1 과제.
- ➖ 이식 기간 동안 source-of-truth가 둘(레거시/모노레포) → 동작 동일성 테스트로 보증 필요.

## 대안 기각 사유

- 내부 리팩터: 운영 리스크 + 경계 오염. trust 별도 레포: 두 자산의 시너지 상실.
